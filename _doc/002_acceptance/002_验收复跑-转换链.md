## 1. 验收项 1：四类转换各配一条真实规则并跑通端到端（对账一致）

**用例**：`com.zifang.z.etl.core.TransformPipelineEndToEndTest`（5 个用例）

| 类别 | 本卡配的那条真实规则 | 落点 |
|---|---|---|
| ① 字段映射 | `id → order_id` 改名 + 落库类型声明（`LONG`/`STRING`/`BIGDECIMAL`/`INT`/`TIMESTAMP`） | `transform.fieldMappings` |
| ② SQL pushdown | **过滤下推** `status = 1`（源表 1000 行 ⇒ 实际只读 334 行）；**聚合下推** `GROUP BY status` + `COUNT(*)`/`SUM(amount)`（1000 行明细 ⇒ 引擎只拿到 3 行分组结果） | `source.pushdown` |
| ③ 行级表达式 | EL（z-util-expr）：`status == 1 ? 'PAID' : (status == 2 ? 'SHIPPED' : 'CLOSED')`；GROOVY（z-script 沙箱）：`amount * 1.13`、`gross_amount - amount` | `transform.expressions` |
| ④ 类型归一 | `status → LONG`（INT 归一成 64 位）、`amount/gross_amount/tax_amount → BIGDECIMAL scale 2`（定点收口） | `transform.typeNormalizations` |
| 附：脚本沙箱 | GROOVY 清洗支付方式：`raw == null ? '' : raw.toString().trim().toUpperCase()` | `transform.scripts` |

**双口径对账读数**（源表 1000 行 / 过滤口径 334 行）：

| 口径 | 读数 |
|---|---|
| 行数 | 源侧 334 = 目标侧 334（`countMatched = true`） |
| 校验和（幂等键多重集） | 源侧 `65f4d902238da9bc` = 目标侧 `65f4d902238da9bc`（`checksumMatched = true`） |
| 物理落库复核 | `etl_trade_order_transformed` 334 行；`COUNT(DISTINCT order_id) = 334` |
| 抽查 `order_id = 1` | `order_no = SO00000001` / `amount = 101.00` / `status = 1` / `status_text = PAID` / `gross_amount = 114.1300` / `tax_amount = 13.1300` / `pay_channel = ALIPAY` |

**下推确实进了源库 SQL**（不是把明细拉回引擎再滤）：`JdbcRowReader.lastExecutedSql()` 实测
`SELECT id, order_no, user_id, amount, status, payment_method, updated_at FROM z_trade_order
WHERE (status = 1) ORDER BY id LIMIT ? OFFSET ?`。

**聚合下推作业**（`trade-order-status-summary`）：读 3 行 / 写 3 行，源侧 3 = 目标侧 3，双口径一致；
`status = 1` 分组：`order_cnt = 334` / `total_amount = 41567.00` / `avg_amount = 124.4500`。

## 2. 验收项 2：沙箱步骤超时/超内存被拦截且 job 失败信息可读（不静默吞）

**用例**：`com.zifang.z.etl.core.SandboxGuardTest`（4 个用例）—— 失败信息原文（证据 `02_sandbox_guard.log`）：

| 场景 | 失败信息原文 |
|---|---|
| 死循环（超时 300ms） | `作业 transform-timeout 执行失败: 转换步骤 [script:runaway] 失败: 脚本执行超时(300ms)，已强制中断` |
| 产出 100 万字符（上限 65536） | `作业 transform-oversize 执行失败: 转换步骤 [script:memory_bomb] 失败: 脚本产出 1000000 字符，超过单步上限 65536 字符（内存越限兜底）` |
| LUA 引擎 | `作业描述不合法: transform.scripts[lua_step] 引擎不支持: LUA（可用: GROOVY / EL；LUA 执行器无沙箱无超时、实测可逃逸 ⇒ 硬拒绝）` |
| 危险调用（`Runtime.getRuntime()`） | `作业 transform-escape 执行失败: 转换步骤 [script:escape] 失败: 脚本执行失败: 脚本被沙箱拦截: startup failed:` |

- **不静默吞**：四种场景都是 job **抛异常失败**，不是「跳过这一步继续跑」；失败后目标表 **0 行**（不留半截数据）。
- **超时**：用 z-script 沙箱**自带**的墙钟超时（`SandboxExecutor` + Groovy `@ThreadInterrupt` 打断死循环）。
- **超内存**：⚠️ **z-script 侧没有内存配额**（TASK-20261012-010 实测结论，零件缺口）⇒
  本仓兜的是**单步产出大小上限**（引擎侧可判定的闸），**不等于** JVM 堆内存配额。
  真正的堆配额需 z-script 仓补（见任务卡「人工执行清单」）。
