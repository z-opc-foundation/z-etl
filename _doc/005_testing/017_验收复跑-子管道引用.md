# 验收复跑 · 子管道引用（`pipeline.ref`）

> 卡面：**管道当视图** —— 已登记的管道可以像源一样被别的管道引用复用：子管道的汇全部换成 collect（只取产出不落地）、不读不写水位与状态、`params` 透传占位符。

---

## 1. 口径与边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | **视图口径，不是触发落库**：子管道声明里的 `jdbc.sink` / `file.*.sink` / `http.sink` / `message.sink` 等汇在执行前一律替换成 `collect.sink` | 引用方要的是「这条管道的产出」，不是「再落一遍库 / 再发一遍 webhook」 |
| 2 | **不碰水位与状态**：子管道用全新 `HeapStateBackend`、无游标存储、无状态快照存储 ⇒ 每次引用全量重算 | 引用方的水位断点续传不能被子管道搅局；视图重算天然幂等 |
| 3 | `params: {k: v}` 透传给子管道占位符（`${...}`，走 `PipelineParams.resolve` 同一套参数白名单与缺失检查） | 同一份子管道定义天天跑不同批次 |
| 4 | **嵌套防护**：`pipeline.ref` 里还能再引用管道，深度上限 8 层（ThreadLocal 计数），超限报 `嵌套超过 8 层`，自引用成环在这里断掉 | 不设防就是无限递归 |
| 5 | 缺 `name` ⇒ 校验期报错；引用不存在的管道 ⇒ 打开时报 `引用的管道不存在`；执行环境没配解析器 ⇒ `需要管道解析器（PipelineRefResolver）` | 三种坏法都点名，不静默跑空 |
| 6 | 解析 SPI：`com.zifang.z.etl.core.spi.PipelineRefResolver`（名字 → `PipelineSpec`）；引擎层用落库管道清单实现（`repository.find`），裸执行器默认没有 | 算子层不认识存储层，靠 SPI 解耦 |
| 7 | 引用节点自己也是源：可声明 `eventTimeColumn` 接父管道的水位 / 断点续传（`AbstractPullSource` 统一口径） | 引用方照样能做事件时间窗口 |

## 2. 复跑命令

```bash
cd z-etl
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -Dtest=PipelineRefTest
```

预期：`Tests run: 6, Failures: 0, Errors: 0`

| 用例 | 覆盖 |
|---|---|
| `refAsView` | 引用已登记管道，子管道的 `field.mapping` 改名列对引用方生效；下游继续加工 |
| `subSinksReplaced` | 子管道声明 `file.csv.sink` ⇒ 引用跑完后**文件不存在**（汇被替换，只取产出） |
| `paramsPassThrough` | `params: {status: PAID}` 填子管道 filter 里的 `${status}` 占位符，只放行命中的行 |
| `selfReferenceBlocked` | 管道引用自己 ⇒ `嵌套超过 8 层`，不无限递归 |
| `rejectsBrokenConfigs` | 缺 `name` / 引用不存在的管道 / 无解析器，三种坏法各自报错并点名 |
| `nestedRefs` | 两层嵌套（parent → mid → base）：base 过滤 + mid 加倍层层生效 |

## 3. 用法示例

```yaml
name: 报表出口
nodes:
  - id: orders          # 引用已登记的「清洗后的订单」管道当源
    type: pipeline.ref
    config:
      name: 清洗后的订单
      params: {status: PAID}     # 可选：填子管道占位符
      eventTimeColumn: created_at # 可选：引用方自己接水位
  - id: agg
    type: window.aggregate
    config:
      keyBy: [city]
      window: {type: tumbling, size: 5m}
      aggregates: [{fn: SUM, column: amount, alias: total}]
  - id: out
    type: jdbc.sink
    config: {table: city_daily, ...}
edges:
  - {from: orders, to: agg}
  - {from: agg, to: out}
```

⚠️ 实测注意：子管道若声明了必填的连接器配置（如 jdbc 源的 `dataSourceRef`），引用时照样要能解析 —— 视图口径换的是**汇**，不是源。
