# 031 验收复跑 —— CEP 状态迁移兼容性

## 口径

1. CEP 部分匹配（`Partial` / `StepMatch`）进键控状态，`serialVersionUID` 固定 1 —— 字段增改不破坏老快照的反序列化。
2. 跑一半（create 已配、pay 未到，pay 非 optional ⇒ 不会段尾封口）→ 执行器关掉快照落库 → **全新状态后端**从快照恢复（`restored` 备注）→ pay 来了照常配成，产出行带着恢复前配到的 `create.type` / `create.amount`。
3. optional 拖尾 + 恢复：恢复进来的老键匹配与新键匹配都在段尾 flush 封口，恢复的键先产出（活跃键表恢复序）。
4. 恢复与封口互不干扰：恢复不触发产出，产出只由事件推进 / 流尾封口决定。
5. 测试隔离坑（本档踩出来的）：`InMemoryPipelineStateStore.load` 在实例 map 未命中时回退读**静态** `TEXT_STATES` —— 同名管道跨测试会串快照。用独立管道名隔离。

## 复跑

```bash
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -pl z-etl-core \
  -Dtest='CepStateMigrationTest'
# 预期：Tests run: 2, Failures: 0, Errors: 0
```

## 用例

| 用例 | 两段喂的事件 | 断言 |
| --- | --- | --- |
| resumeMidPattern | 段1 create(amount=10) → 段2 pay | 段1 0 产出、快照落库、无恢复备注；段2 恢复备注 + 1 条匹配（create.* 从恢复状态带出） |
| resumeWithOptionalTailSealed | 段1 键1 create → 段2 键2 create | 段2 封口 2 条：键1（恢复的键先出）与键2，pay# 均 0 |

全量：`mvn -o test` → 208 个用例（core 203 + web 5）。

## 注意

- 内存存储的静态文本镜像（`TEXT_STATES`）是为「与落库实现走同一条序列化路径」服务的跨实现核对口 —— 测试里同名管道要隔离。
- 中途杀进程的端到端口径另见 `WatermarkResumeAfterKillTest`（子进程 kill → 重启续跑）；本档管的是状态形状的可序列化兼容。
