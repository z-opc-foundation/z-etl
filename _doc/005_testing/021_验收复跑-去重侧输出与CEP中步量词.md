# 验收复跑 · 去重重复侧输出（`duplicateTo`）与 CEP 中步量词

> 卡面：**被挤掉的行有去处** —— `dedup`（keep=first）挤掉的行声明 `duplicateTo` 后原样走侧输出（与窗口 `lateTo` / filter `rejectedTo` 同一套旁路口径）；顺带验证 CEP 中间步骤 `times: "1,"` 的组合匹配。

---

## 1. 口径与边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | **丢弃判定不变**：keep=first 且该键见过 ⇒ 挤掉（`dropped` 计数照旧）；声明 `duplicateTo` 后被挤掉的行**原样**走旁路 | 重复审计 / 死信落表要原始行 |
| 2 | 侧输出接的是**全部被挤掉的行**：真重复（同指纹）与「同键新版本」都算 —— 两者在计数里可分（`duplicates` / `same-key-new-version`），在侧输出里合流 | keep=first 的语义就是「同键后到全挤」 |
| 3 | **不声明 `duplicateTo` 行为不变**：只丢计数；`keep: last` 永不挤行 ⇒ 侧输出恒空 | 向后兼容 |
| 4 | `duplicateTo` 指向不存在的节点 ⇒ 开跑前报错点名（执行器旁路检查） | 不等到运行时静默丢 |
| 5 | **列下推**：侧输出目标需要的列并入 dedup 的上游需求 | 被挤的行要全须全尾到旁路 |
| 6 | **CEP 中步量词**（已支持能力的用例固化）：中间步骤 `times: "1,"` 可续吃同类事件；旧中步还能被后续事件推进 ⇒ 两种长度的匹配都产出（保守口径「宁多配」）；续吃版在部分匹配表前头 ⇒ `ship#` 大的先出 | 文档化组合语义，防止误以为是 last-step-only 特性 |
| 7 | CEP 产出行里 `步骤名.列` 取**该步第一条事件**的值 | 产出行形状口径（与 018 一致） |

## 3. 用法示例

```yaml
- id: dedup
  type: dedup
  config:
    keyBy: [order_id]
    keep: first
    duplicateTo: dead-letters      # 被挤掉的行落死信
```

⚠️ 实测注意：CEP 中步量词的组合匹配里，「续吃版先出」是部分匹配表顺序的自然结果 —— 断言顺序前先想清楚哪条先产出。
