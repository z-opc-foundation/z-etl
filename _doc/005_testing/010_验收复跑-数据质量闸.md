# 验收复跑 · 数据质量闸（`assert` 算子）

> 卡面纪律：**不合格的数据不许悄悄流下去** —— 逐行判定当场处置，结算期判定流结束才算账。

---

## 1. 两类判定

| 类别 | 判定项 | 什么时候有结论 | 结论不符怎么办 |
|---|---|---|---|
| 逐行判定 | `expression`（表达式为假即违规）/ `inRange`（区间）/ `allowedValues`（允许值）/ `unique`（唯一性） | 边流边判，撞上就判 | `fail` 抛错中止 / `reject` 走 `rejectedTo` 旁路 / `count` 只计数 |
| 结算期判定 | `minRows` / `maxRows` / `exactRows`（行数）/ `notNullRate`（列非空率） | 流结束（`close()`）才有结论 | `fail`/`reject` 抛错 / `count` 只计数 |

## 2. 口径与边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | `mode=reject` **必须**声明 `rejectedTo` | 违规行要有去处；没去处就只能失败（不许静默丢） |
| 2 | 违规行走旁路时**不算失败** | 脏数据有去处就是「处理完了」，不该把作业打挂 |
| 3 | 结算期判定失败时**数据已落库** | 质量闸 ≠ 事务；但水位不落库 ⇒ 下轮重跑 |
| 4 | `close()` 结算**幂等** | 执行器会关两次算子（正常收尾 + finally 兜底），第二次不许再抛 |
| 5 | 唯一性追踪有上限（`maxTracked`，默认 100 万） | 内存兜底；超限明确报错，不静默放弃校验 |
| 6 | 断言读的列被投影下推**保活** | 裁掉被断言的列 ⇒ 校验的是空值（假合格） |

## 3. 复跑命令

```bash
cd z-etl
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -Dtest=AssertOperatorTest
```

预期：`Tests run: 8, Failures: 0, Errors: 0`

| 用例 | 覆盖 |
|---|---|
| `passesValidRows` | 全合规 ⇒ 行原样流下去（表达式 / 区间 / 允许值 / 行数下限一起判） |
| `failsOnViolation` | 默认 `fail`：表达式不成立 ⇒ 整条流水线失败，报错点名节点与原因 |
| `rejectsViolatingRows` | `mode=reject`：违规行走旁路，好数据进主链路，违规行不静默丢 |
| `countsViolations` | `mode=count`：不处置，违规数记在节点指标里 |
| `settlesRowCount` | 结算期判定：行数不足 ⇒ 流结束时失败 |
| `detectsDuplicates` | 唯一性：撞上重复值即失败 |
| `checksNotNullRate` | 非空率：流结束时结算，空值超标即失败 |
| `rejectsModeWithoutRejectedTo` | `mode=reject` 没声明 `rejectedTo` ⇒ 跑之前就报错 |
