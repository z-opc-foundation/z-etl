# 验收复跑 · 线性作业层的连接器（job 的输入 / 输出类型）

> 口径：**线性层与 DAG 层共用同一批连接器实现**。
> job 描述里写 `source.type: file.csv`，跑起来的就是 DAG 层那个 `file.csv.source` 算子
> —— 不是另写一套文件解析、不是另写一套水位口径。
>
> 全部验收在**本地 H2 + 临时目录 + 本地 HTTP 服务**上跑，**不连任何真实库 / 生产库 / 外网**。

---

## 1. 类型映射（job 描述 → 连接器算子）

| job 描述里的类型 | 源算子 | 汇算子 | 必填 options |
|---|---|---|---|
| `jdbc`（默认） | `jdbc.source` | `jdbc.sink` | —（用 `dataSourceRef` / `table`） |
| `file.csv` | `file.csv.source` | `file.csv.sink` | `path` |
| `file.json` / `ndjson` | `file.json.source` | `file.json.sink` | `path` |
| `file.xlsx` / `excel` | `file.xlsx.source` | — | `path` |
| `http` / `rest` / `webhook` | `http.source` | `http.sink` | `url` |
| `inline` / `static` | `inline.source` | — | `rows` |
| `script` / `groovy` | `script.source` | — | `script` |
| `message` / `mq` / `kafka` | `message.source` | `message.sink` | `topic` |
| `console` / `collect` | — | `console.sink` / `collect.sink` | — |

## 2. 口径

- **非 JDBC 侧不解析数据源引用**：`dataSourceRef` / `table` 不用写（占位 DataSourceProvider 也不会被触发）。
- **JDBC 专属配置在非 JDBC 侧直接报错**：`where` / `orderBy` / `pushdown` / `columns`
  （不静默忽略 —— 免得以为下推生效了）。
- **断点续传不变**：页级提交（写成功才推进水位）；文件 / HTTP / 消息源按「水位 + 平局列」接力，
  过滤口径与 JDBC 源一致（`(w > ?) OR (w = ? AND tb > ?)`）。
- **对账分两种口径**：
  - 两侧都是 JDBC ⇒ 整表扫描（行数 + 键多重集校验和）；
  - 任一侧不是 JDBC ⇒ 本轮行内口径（源行 vs 写出行的幂等键多重集），履历里注明。

## 3. 复跑命令

```bash
cd z-etl
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -Dtest=LinearConnectorJobTest
```

预期：`Tests run: 4, Failures: 0, Errors: 0`

| 用例 | 覆盖 |
|---|---|
| `csvSourceToHttpSinkWithIncrementalResume` | file.csv 源 → http 汇；跑完落水位；追加一行后第二轮只搬增量（只多发 1 次 HTTP）；行内口径对账一致 |
| `inlineSourceToJsonFileSink` | inline 源（零 IO）→ file.json 汇（NDJSON 文件落盘） |
| `jsonSourceToMessageSink` | file.json 源（NDJSON）→ message 汇（`etl_message_outbox` 落 2 条） |
| `rejectsBadConnectorTypes` | `source.type` 不支持 ⇒ 报错；`options.path` 缺失 ⇒ 报错 |
