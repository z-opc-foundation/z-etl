## 实施中的口径澄清（写测试时与引擎对齐）

- `*` 中间步的匹配路径：引擎「宁多配不少配」哲学下，`CREATE → items* → PAY` 里
  每个循环长度（items# = 2/1/0）都是合法匹配各自产出——与 Flink NFA 的多运行语义一致；
  拖尾 `*` 步**被进入后**随每次续吃重发（开放式量词的既有口径），**从未进入**时才靠
  flush 封口补产出（items# = 0）。
- 整行指纹的数值归一要**统一 scale**（`stripTrailingZeros().toPlainString()`）——
  `"100"` 与 `100.0` 的 toPlainString 不同（scale 不同），不归一就是假性不等。

## 生产 500 事故与修复（同日晚，r2 修复镜像）

**现象**：公网 `https://opc.zopc.top/etl/`（裸前缀）→ Whitelabel 500。此前所有验证都走
`/etl/index.html`（200），裸 `/etl/`、`/etl` 从未被探过——验证口径漏了「目录式根路径」。

**根因**（Pod 日志 5.2MB 里翻出，stdout 为空、日志在容器内 `/log/test.log`——z-boot 日志落盘口径）：
`/etl/` 被 `EtlPrefixRewriter` rewrite 成 `/` → Spring Boot welcome-page 机制对 `/` 做
**forward 到 index.html** → 携带改写 URI 的请求包装器进 Tomcat forward 的
`ApplicationHttpRequest.setAttribute` 属性同步 → **无限递归**（同一行几千帧）→
StackOverflow → 500。本地 nginx 剥前缀形态下后端看到的是真 `/`（无包装器）⇒ 从未触发。

**修复**（`EtlPrefixRewriter` r2，两条铁律）：
1. **只在 REQUEST 分发时重写**——FORWARD / ERROR 分发放行原始请求（welcome-page 与
   错误页都靠 forward，不该再碰改写）；
2. **裸 `/etl`、`/etl/` 不 rewrite，302 重定向**到 `/etl/index.html`（GET 最朴素路径）。

**验证**（`20261126-e252803r2` 镜像，集群 + 本地 aio 同步滚动）：
- 回环：`/etl/` 302、`/etl` 302、`/etl/index.html` 200、`/etl/api/etl/operators` 200；
- 公网（node 探针）：`/etl/` 302 → `http://opc.zopc.top/etl/index.html` 200、API 200；
- 本地 aio 8093：`/etl/` 302 → index 200。
- 用例 280 全绿（rewriter 根别名断言更新为「不改写走重定向」口径）。

## 画布编辑器三连修（同日晚，r4 镜像）

CEO 画布实测三处别扭，全部根修：

1. **节点不能往上拖**：拖拽钳制 `Math.max(8,…)` 把坐标钉在正区。⇒ 放开到
   `ED_DRAG_MIN=-1800`，SVG 连线层加 **-2000 负偏移 viewBox**（`left/top=-2000px` +
   `viewBox="-2000 -2000 …"`）⇒ 负坐标节点与连线照常渲染，真·无限画布；
   再补**拖近可视边缘自动跟随平移**（36px 触发边距，Figma 手感）。
2. **画布底部留白**：固定高度 `calc(100vh - 250px)` 与真实面板链不匹配。⇒ 编辑面板打开时
   `display:flex;column;height:calc(100vh - 34px)`（= 视口 − main 内边距 − 边框），
   画布 `flex:1` 吃掉剩余高度。
3. **右侧没填满**：三列（调色盘/画布/配置）改为 `ed-shell{flex:1;min-height:0}` 等高拉伸，
   调色盘与配置列各自滚动、与画布同底。

**顺带**：打开编辑器即**内容自适应**（`edZoomFit` 按全部节点包围盒取缩放与平移，
负坐标节点一并入画，上限 1.2×）。

**验证**（本地 aio 浏览器实测 + r4 镜像滚动集群）：面板满高 822（视口 856）、
三列等高 665、底边 823 对齐；负坐标节点接受（-300/-500px）且连线渲染正常；
