# 验收复跑 · 投影下推（列裁剪）

> 卡面纪律：**错了就是静默丢数据** ⇒ 逐条设保守边界 + 一条「优化前后结果一致」的护栏用例。

---

## 1. 规则与边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | 只对 `jdbc.source` 生效 | SQL 投影是确定的；文件 / HTTP / 消息源的 `columns` 语义各不相同 |
| 2 | 源必须**已声明列清单** | 裁剪结果 = 声明列 ∩ 需要的列 ⇒ SQL 一定有效；没声明（全列）不敢猜 |
| 3 | 链上必须有 `field.mapping` | 整行替换语义 ⇒ 输出列确定 ⇒ 下游要什么才清晰 |
| 4 | `eventTimeColumn` / `resume.tiebreakColumn` **必保** | 裁掉 ⇒ 水位失效 ⇒ 增量悄悄变全量（隐性数据事故） |
| 5 | `join` / `script(mode=row)` / 多路异构合并不裁 | 列集合不可知 |
| 6 | 表达式 / 脚本的列引用按**候选**提取（不排除关键字） | 误判只会多留一列（安全）；少留才是事故 |

传播算法（DataFusion 形状）：从汇出发**逆拓扑序**回推「每个节点被需要的列」；
行保持算子原样传给上游；`field.mapping` 把目标列翻译成源列；到源处与声明列求交即得投影。

## 2. 运行时即优化

- 执行器跑之前先优化一遍（**深拷贝后改写**，不动调用方的声明）；
- 优化备注（每条规则做了什么 / 为什么没做）写进运行结果（`result.getNotes()`）；
- `explain()` 同样基于副本 ⇒ 不会把注册在库的声明改坏。

## 3. 复跑命令

```bash
cd z-etl
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -Dtest=ProjectionPushdownTest
```

预期：`Tests run: 6, Failures: 0, Errors: 0`

| 用例 | 覆盖 |
|---|---|
| `narrowsSourceColumns` | 收窄成「映射源列 + 表达式引用列」，没人用的列被裁 |
| `keepsWatermarkAndTiebreakColumns` | 水位列 / 平局列必保 |
| `skipsWhenSourceHasNoColumnList` | 源没声明列清单 ⇒ 不裁 + 备注说明原因 |
| `skipsWithoutFieldMapping` | 链上没有 `field.mapping` ⇒ 不裁 + 备注说明原因 |
| `skipsWithJoin` | join 在链上 ⇒ 两侧都不裁 |
| `optimizedPlanProducesIdenticalRows` | **护栏**：优化前后跑出的行逐字段一致 |
