## 本波落了什么

| 增量 | 落点 | 一句话 |
|---|---|---|
| 失败运行也落履历 | `etl_pipeline_run` 加 `status` 列（SUCCESS/FAILED） | 原先 `saveRun` 只在成功路径调用 ⇒ 失败即黑箱。现在 `PipelineEngine.run` 失败（含重试耗尽）也落一条 FAILED，异常摘要进 notes（履历分隔符「；」做转义）；老库 `EtlSchema.ensure` 走既有补列口径幂等加列，旧行缺省当 SUCCESS |
| 运行总览 API | `GET /api/etl/pipelines/overview`（`EtlPipelineService.overview`） | 近 24h/7d 窗口计数 + 每条流水线最近一次运行（状态/耗时/读写量）+ 调度登记（cron/停用态/下次触发）+ 跨流水线最近运行明细（limit ≤ 200）；仓储新增 `recentRuns(limit)`（Jdbc/InMemory 双实现，行映射抽 `mapRunRow` 共用） |
| 数据源登记 | `etl_datasource` 表 + `JdbcDataSourceRegistry` | 登记/更新（password 留空 = 保留旧密码）/删除/列表/`testConnection`（真握手 + SELECT 1，错误摘要截 300 字）；仓储层返回全量行，**掩码口径在 web 层**（`EtlDataSourceController` 列表一律 `********`，密码不出网） |
| 数据源 REST | `EtlDataSourceController`（`/api/etl/datasources`） | GET 列表 / POST 登记 / DELETE / POST `test`（已登记条目 password 留空 = 用库存真值握手） |
| Provider 闭环 | `RegistryDataSourceProvider` | 内置 `DataSourceProvider` 默认实现改为**按登记表解析** `dataSourceRef`（按 updated_at 失效缓存）；宿主 z-dms Bean 仍可 `@ConditionalOnMissingBean` 顶掉（声明序：registry 版在前、报错占位在后） |
| 组件七视图 | `@yuku123/z-etl-component@0.2.0` | 新增 `OverviewView`（统计卡 + 流水线健康 + 最近运行）与 `DataSourcesView`（表单 + 列表 + 行级测试连接）；EtlApp 左树语义四组：数据接入 / 作业管理 / 运维治理 / 算子库；hash 规范键 `#ds/#overview`，别名 `#datasources` 兼容 |
| 主壳接线 | z-team-component 0.2.166 EtlWorkbench + SystemWorkbench | 数据治理子菜单 **数据源管理/源算子/汇算子/作业模板/调度/作业实例/运行总览** 七叶（原「数据源/输出源」更名「源算子/汇算子」——它们是算子目录不是数据源） |
| 内置控制台 | jar 内 `static/index.html` 同步四组七页签 | vanilla 版补 `#ds`（表单+列表+行级测试）与 `#overview`（统计卡+双表）两个 section 与渲染函数 |
| 顺手修 | `PipelineExecutor` 补 `setFinishedAt` | 成功运行 finishedAt 恒 0 的预存缺陷在总览里显形（耗时负数）；前端 `fmtMs` 对 <0 显示 `—` 兜底旧行 |
