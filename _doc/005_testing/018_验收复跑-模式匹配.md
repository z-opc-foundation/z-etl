# 验收复跑 · 模式匹配（`cep.pattern`）

> 卡面：**单流上的 Flink CEP** —— 步骤序列 + 次数量词 + within 时间窗：「下过单又付了款」「连续三次失败后登录成功」这类序列侦测不用再手写状态机。

---

## 1. 口径与边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | **保守匹配口径**：一个事件既延续旧的部分匹配、又开启新匹配（两件事都做）；**推进即取代** —— 匹配推进到下一步后原匹配不保留 | 不做 strict/relaxed/skip 那套策略细分；「推进即取代」避免同一路径在同一步骤反复产出重复匹配 |
| 2 | **次数量词** `times`：缺省 `1`（恰好）；`"n"` 恰好 n 次；`"n,"` 至少 n 次（最后一步未封顶 ⇒ 产出后部分匹配继续吃同类事件，每多一条多产出一条）；`"n,m"` 闭区间 | Flink `times()` / `oneOrMore()` 的最小可用面 |
| 3 | **产出行形状**：行 = 最后一条事件的行 + 每步 `步骤名.列`（取该步第一条事件）+ `步骤名#`（该步命中次数） | 既能看每步内容又能看量词命中数；`步骤名.` 前缀天然不与原列冲突 |
| 4 | **within 超时**：声明 `within` 后，行必须带事件时间（否则丢弃并计数 `no-event-time-dropped`）；事件时间距起步超过 within 的部分匹配丢弃（`expired`）；水位推进时起步早于「水位 − within」的全部清掉 | 模式有时间语义才有业务意义；水位口径与窗口 / 区间连接一致 |
| 5 | **防爆炸**：每键部分匹配数上限 `maxPartials`（缺省 64），超出丢最老并计数（`partial-overflow-dropped`） | 分支 + 未封顶量词会让部分匹配无界涨 |
| 6 | 键控：`keyBy` 声明键列（`Keys.computeValues` 纯值键）；不声明 = 全流一个键（全局模式） | 与 join 家族 / aggregate 同一套键口径 |
| 7 | 步骤条件求值：`engine` 缺省 `EL`（z-util-expr 白名单 EL）；`GROOVY` 走 z-script 沙箱；LUA/JS 硬拒绝 | 与 filter / map 同一套安全口径 |
| 8 | 状态可序列化（部分匹配进键控状态 ListState）⇒ 能进检查点；活跃键清单挂哨兵键 `\u0000cep-active-keys`（与 interval.join / dim.join 的哨兵不同名） | 断点续传口径与其它有状态算子一致 |

## 2. 复跑命令

```bash
cd z-etl
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -Dtest=CepPatternOperatorTest
```

预期：`Tests run: 6, Failures: 0, Errors: 0`

| 用例 | 覆盖 |
|---|---|
| `basicSequence` | create → pay 序列，两个订单各出一条匹配；`create.type`/`pay.type`/`create#`/`pay#` 逐字段断言；`matched` 计数 |
| `openEndedTimes` | `times: "1,"` 未封顶：两条 PAY 各出一条匹配（`pay#` = 1 和 2），行是最后一条 PAY 的 |
| `withinExpiry` | PAY 晚于 within（6 分钟 > 5 分钟）⇒ 不配对，`expired` 计数；行必须带事件时间 |
| `keysIsolated` | 不同 `order_id` 的 create/pay 不互配（纯值键隔离） |
| `partialCap` | `maxPartials: 1`：同键第二个 CREATE 把第一个挤掉（`partial-overflow-dropped` = 1），最新的能配成 |
| `requiresSteps` | 缺 `steps` ⇒ 校验期报错并点名 |

## 3. 用法示例

```yaml
- id: cep
  type: cep.pattern
  config:
    keyBy: [order_id]
    within: 5m
    steps:
      - {name: create, expression: "type == 'CREATE'"}
      - {name: pay,    expression: "type == 'PAY'", times: "1,"}
```

⚠️ 实测注意：未封顶量词（`"n,"`）+ 高基数键下部分匹配会持续增长 —— 生产上要么给 `within`（水位帮忙清），要么压低 `maxPartials`。
