# 验收复跑 · 保存点（savepoint：状态快照 + 水位游标打包迁移）

> 卡面：**作业要能搬家** —— A 环境跑到一半导出，B 环境灌回（可换名）直接增量续跑。

---

## 1. 口径与边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | 保存点 = **键控状态快照（Base64）+ 复合水位游标** 打包成自描述 JSON（版本号 + 导出名 + 导出时间） | Flink savepoint 口径：可搬运的运行时状态载体 |
| 2 | **导出纯读**：状态存储与水位存储的现场纹丝不动（两次导出的状态字节逐位一致） | 导出不能算「动过状态」 |
| 3 | **灌回覆盖写**：目标管道原有的状态快照与水位被报文内容替换 | 恢复语义就是「以报文为准」 |
| 4 | 可**换名迁移**：`importSavepoint(json, targetName)` 灌到新名字下（作业复制）；水位记录的 jobName 跟随目标名 | Flink 恢复也可指定新作业 |
| 5 | 报文校验：版本不支持 / 缺 `pipeline` / 空报文（既无状态也无水位）都拒绝 | 坏报文不能静默灌成空状态 |
| 6 | 空管道（从没跑过）导不出（明确报错「先跑一次再导出」） | 没东西可搬就该直说 |
| 7 | 报文格式版本 v1；`fromJson` 按版本解释结构 | 将来改结构有退路 |

## 2. 入口

| 入口 | 用法 |
|---|---|
| 代码 | `engine.exportSavepoint(name)` / `Savepoints.toJson(sp)` / `engine.importSavepoint(json[, targetName])` |
| Web | `GET /api/etl/pipelines/{name}/savepoint` 导出；`POST .../savepoint/import` 灌回（body 可带 `{"targetName": "新名"}`） |

## 3. 复跑命令

```bash
cd z-etl
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -Dtest=SavepointTest
```

预期：`Tests run: 5, Failures: 0, Errors: 0`

| 用例 | 覆盖 |
|---|---|
| `exportCarriesStateAndWatermarkWithoutMutating` | 导出带状态快照 + 复合水位（`updated_at` + 平局列 `id` + `lastMode=auto`）；两次导出状态字节一致（导出不动现场） |
| `importMigratesJobToFreshEnvironment` | **两环境迁移实证**：A 环境跑 10 行 → 导出 → B 环境（全新 H2 与存储，源里 12 行）灌回 → 只搬 2 条增量，目标表 2 行（目标从空开始只落水位之后） |
| `importToRenamedPipeline` | 同一份报文灌到 `mig-copy` 名下照样续跑；水位记录 jobName = `mig-copy` |
| `validationRejects` | 坏版本（99）/ 缺 pipeline / 空报文都拒绝 |
| `emptyPipelineCannotExport` | 从没跑过的管道导出 ⇒ 明确报错 |

⚠️ 实测注意：`InMemoryPipelineStateStore` 有一面 static 的 base64 文本镜像（跨实现核对用），同一 JVM 内跨实例可见 ⇒ 「空管道」用例必须用**从未在任何用例里跑过的名字**，别复用名字。
