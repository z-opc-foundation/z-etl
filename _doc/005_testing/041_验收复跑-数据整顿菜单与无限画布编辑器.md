## 交付内容

1. **控制台菜单逻辑重排**（CEO 口径「插件 / 数据源 / 输出源 / 中间是模板 / 调度 / 作业」）：
   左树改为五组——数据源（源算子目录）、输出源（汇算子目录）、模板（列表 + ＋新增模板 + 原文直登）、调度、作业；

4. **主壳接入**：z-team 系统面 `SystemWorkbench` 新增「数据整顿」组（五子菜单 → `/etl/:view`），
   `SystemShell` 挂 `EtlWorkbench`（iframe 挂同源 `/etl/index.html#<view>`，照知识中台先例）；
   主壳 vite 与 e2e/system-mode 台子各补 `^/etl/` 剥前缀代理到 :8092；
   控制台按 `location.pathname` 前缀 `/etl/` 自动给 API 调用补同段前缀（独立跑不受影响）。

**复测顺序 = 起服务 → 建干净 worktree 发版 → 抬主壳 → 重建 aio 前端镜像 → 实时浏览器验收**。
浏览器验收（e2e 系统壳台 + CDP trusted click，Node 原生 WebSocket 驱动本机 headless Chrome）挖出三个真 bug：

1. **iframe hash 不跟路由**（useParams 恒空）：SystemShell 的 SYSTEM_ROUTES 是手动 pathname
   匹配（matchSystemPath），element 渲染在 Router 参数上下文之外 ⇒ `useParams()` 永远拿不到 view ⇒
   iframe 恒停 `#templates`。修：`EtlWorkbench` 改从 `useLocation().pathname` 取尾段。
2. **调度/作业 hash 键不一致**：控制台内部 tab id 是单数 `sched/job`，壳层菜单路由发复数
   `schedules/jobs` ⇒ 控制台 TABS 不认识、静默落模板页。双修：控制台加 `TAB_ALIAS`
   入站归一（兼容 `#schedules/#jobs` 深链）；壳层 `HASH_KEY` 映射发规范键。
3. **iframe 高度塌成 150px**：`.shell{flex:1}` 挂载点是 SystemShell 的 `.main`（block、
   overflow:auto），flex:1 对 block 父级无效 ⇒ iframe 用默认高度 150px（左树被裁、内容区一片白）。
   修：`.shell{height:100%}`。⚠ CognitionWorkbench 是同一份 CSS 形态，疑似同病，未动（另案）。

**验收证据**：`mvn clean test` 247 用例全绿（core 239 + web 8）；
nginx 双端口 curl：`/etl/index.html` 200（title=z-etl 控制台）、`/etl/api/etl/operators` 返回算子 JSON；
e2e 台 trusted click 逐步断言：数据源→`#sources`、流水线模板→`#templates`、作业→`#job`（iframe 内作业页渲染、
左树五组 + 模板叶子在位）；iframe 视口 1182×813 满高。
