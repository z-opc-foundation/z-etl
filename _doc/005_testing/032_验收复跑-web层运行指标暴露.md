# 032 验收复跑 —— web 层运行指标暴露

## 口径

1. `GET /{name}/runs`（service.history）里每次运行带观测三件套：`recordsRead` / `recordsWritten` / 每节点计数快照（`nodeMetrics`）。
2. 逐节点指标：`records-in`（执行器派发时打点，变换与汇节点上可见）+ `elapsed-nanos`（派发处量出的处理耗时，全部节点可见）。
3. 运行履历带 `startedAt`；`durationMs` 口径只在当场返回的 `PipelineRunResult` 上可靠（履历往返不承诺时间戳完备）。
4. 源节点不打 `emitted` 计数（源直接产出，`records-in` 从下游节点的视角计）—— 断言口径以 `fm` / `sink` 的 `records-in` 为准。
5. 全程本地 H2（源表 5 行 → field.mapping → 目标表 upsert），不连生产库。

## 复跑

```bash
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -pl z-etl-web \
  -Dtest='EtlPipelineMetricsTest'
# 预期：Tests run: 1, Failures: 0, Errors: 0
```

## 用例

| 用例 | 链路 | 断言 |
| --- | --- | --- |
| historyExposesMetrics | 登记 → run → history(1) | 读 5 / 写 5；fm、sink 各 records-in = 5；三节点都有 elapsed-nanos ≥ 0；startedAt > 0 |

全量：`mvn -o test` → 209 个用例（core 203 + web 6）。

## 注意

- `records-in` 是「下游视角」的计数：某节点的 records-in = 上游派发给它的行数；源节点的产出量看 `recordsRead`（总口径）。
- 每节点细粒度耗时验收（重活节点明显更慢）另见 core 层 `NodeMetricsTest`。
