# 验收复跑 · 区间连接（`interval.join`）

> 卡面：Flink 的 {@code IntervalJoin} 口径 —— 两路流按「关联键 + 事件时间区间」两两配对。

---

## 1. 与普通 `join` 的分工

| | `join`（构建/探测） | `interval.join`（区间连接） |
|---|---|---|
| 语义 | 右表按关联键只留**最新一条**，左来一条查一次 | 两边都缓存；事件时间相差 ≤ `within` 的行**两两配对** |
| 典型场景 | 订单 × 客户维表（要维表的最新属性） | 订单流 × 物流轨迹流（按「下单后 5 分钟内」关联） |
| 产出 | 每条左行至多一条 | 每个配对一条（2 左 × 2 右全在窗口内 = 4 条） |
| 状态清理 | 覆盖写（每键一条） | 水位 − within 之前的缓存清掉 |

## 2. 口径与边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | **必须带事件时间** | 没有事件时间的行没法配对 ⇒ 丢弃并计数（`no-event-time-dropped`），不静默装作关联上 |
| 2 | `within` 必填（Durations 口径：`500ms/30s/5m/2h/1d`） | 没有区间就没有「区间连接」 |
| 3 | 每对只发一次（后到的那条触发） | 与 Flink 的 IntervalJoin 产出一致 |
| 4 | 水位到期清理（`expired` 计数） | 内存只随「窗口内流量」涨，不无界增长 |
| 5 | 缓存行进键控状态（可序列化） | 断点续传口径与其它有状态算子一致 |
| 6 | `joinType: inner`（默认）/ `left` | 左侧没命中也发，右侧列补 null（与普通 join 同口径） |
| 7 | 同名列右侧加后缀（`rightSuffix`，默认 `_right`） | 与普通 join 同口径 |
| 8 | 两条入边 + `left`/`right` 指名到位（跑之前校验） | 与普通 join 同口径 |

## 3. 复跑命令

```bash
cd z-etl
JAVA_HOME=$(/usr/libexec/java_home -v 17) mvn -o test -Dtest=IntervalJoinOperatorTest
```

预期：`Tests run: 7, Failures: 0, Errors: 0`

| 用例 | 覆盖 |
|---|---|
| `matchesWithinInterval` | 区间内配对：2 条左 × 1 条右全在窗口内 ⇒ 2 条拼行（同名列加后缀） |
| `noMatchOutsideInterval` | 相差 4s > within 1s ⇒ 不配对 |
| `leftOuterEmitsUnmatched` | `joinType: left`：左侧没命中也发（右侧列补 null） |
| `crossPairsEmittedOnce` | 2×2 全在窗口内 ⇒ 4 对（笛卡尔积，每对只发一次） |
| `expiresOldEntries` | 水位 − within 之前的缓存被清掉并计数（`expired` ≥ 2） |
| `rowsWithoutEventTimeDropped` | 没事件时间的行丢弃并计数 |
| `requiresWithin` | 没声明 within ⇒ 跑之前就报错 |
